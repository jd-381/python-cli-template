# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## What this repository is

This is a **GitHub template repository** for Python CLI apps built with [Typer](https://typer.tiangolo.com/) and managed with [uv](https://github.com/astral-sh/uv). It is not itself a finished CLI — it's meant to be used via GitHub's "Use this template," after which a one-time GitHub Actions workflow renames everything to the new project's name.

**Do not "clean up" the placeholder names.** `template_package` (the package/import name) and `template-cli` (the CLI executable / distribution name) are literal placeholders, string-replaced by `.github/workflows/initialize-repository.yml` via `sed`. If you're editing this repo *as the template itself* (not a repo created from it), any change touching these names needs to stay consistent across:
- `Makefile` (`PACKAGE_NAME`, `CLI_NAME` variables)
- `pyproject.toml` (`name`, `project.scripts` entry, `tool.hatch.build.targets.wheel.packages`)
- `template_package/main.py` (the `version("template-package")` call)
- `CONTRIBUTING.md` and `templates/TEMPLATE_README.md`
- the `sed` patterns inside `initialize-repository.yml` itself

If you're instead working in a repo that was *created from* this template, these will already have been replaced with real names — check `Makefile`'s `PACKAGE_NAME`/`CLI_NAME` to see what they are here.

## Common commands

- `make deps` — `uv sync --dev` + install pre-commit hooks
- `make validate` — run lint, format, test, and hooks (same checks CI and pre-commit run)
- `make lint` — `ruff check .`
- `make format` — `ruff format .`
- `make test` — `pytest` (run a single test: `uv run pytest tests/test_hello.py -k test_name`)
- `make docs` — regenerate `USAGE.md` from the live Typer app; **never hand-edit `USAGE.md`**
- `make hooks` — run the baseline pre-commit hooks (trailing whitespace, EOF, YAML/TOML validity, etc.); skips `ruff`/`ruff-format`/`pytest`/`docs` since those are already covered by the targets above
- `make install` / `make upgrade` — install/reinstall the CLI globally via `uv tool install`
- `make github` — configure branch protection via `gh` (`.github/setup-branch-protection.sh`)

Run `make` with no args for the full command list.

## Architecture

- `template_package/main.py` — root Typer app. Registers sub-apps with `add_typer()`, configures Rich-formatted logging, exposes `--version`/`-v` via a callback. Has no commands of its own — it's purely a container.
- `template_package/commands/` — one module per top-level command, each with its own `app = typer.Typer(...)` and a `*Service` class holding the actual logic:
  - `hello.py` — **single-command pattern**: `invoke_without_command=True`, logic runs directly off `@app.callback()`. Use this shape for a command with no subcommands.
  - `mail.py` — **multi-subcommand pattern**: `invoke_without_command=False`, `no_args_is_help=True`, each subcommand is a separate `@app.command()`. Use this shape when a command needs subcommands (`fetch`, `delete`, `error` here).
  - Both patterns follow the same error-handling convention: wrap the service call in `try/except`, log the exception via the module-level `LOGGER`, then `raise typer.Exit(code=1)`.
- `template_package/common/` — shared helpers:
  - `cli_utils.py` — `DEBUG_OPTION`, a reusable `Annotated` type for the `--debug` flag with a callback that bumps the root logger to `DEBUG`. Add this to any new command that should support `--debug`.
  - `logger_utils.py` — Rich markup color helpers (`cyan`, `green`, `magenta`, `red`, `yellow`) for log messages.
- `template_package/models/` — plain data: `Language` (str `Enum`), `Mail` (frozen `dataclass`) + an in-memory `mail_data` list standing in for a real data source.
- `tests/` — pytest, using Typer's `CliRunner` for command-level tests (`test_hello.py`, `test_mail.py`) plus direct service-class tests (`test_services.py`). `test_mail.py` uses an `autouse` fixture to reset the shared `mail_data` list between tests since it's mutated in place.

**Adding a new command:** create a module in `commands/`, follow the single- or multi-subcommand pattern above (whichever fits), put the logic in a `*Service` class (not directly in the Typer callback — keeps it testable without `CliRunner`), register the app in `main.py` via `app.add_typer(...)`, add tests for both the CLI surface and the service class, then run `make docs` to refresh `USAGE.md`.

## Generated / special files

- `USAGE.md` — generated by `typer template_package.main utils docs`. Both the `docs` pre-commit hook and the CI `docs` job fail if `git diff USAGE.md` is non-empty after regenerating, so run `make docs` after any command/option change.
- `templates/TEMPLATE_README.md` — the README that becomes `README.md` once a real project is initialized (the init workflow moves it and deletes `templates/`). Only relevant pre-initialization; edit this instead of `README.md` if you're changing what an *initialized* project's README says.
- `README.md` at the repo root (pre-init) documents the template itself, not a generated project — don't confuse the two when editing.

## Pre-commit / CI

- `.pre-commit-config.yaml` runs Ruff (lint --fix, format), the **full pytest suite**, and doc regeneration on every commit (`always_run: true`). Commits are slower than a lint-only hook set by design — the tradeoff is that CI never sees a red build for these checks.
- `.github/workflows/ci.yml` reruns the same checks as separate jobs (`lint`, `format`, `test`, `docs`, `pre-commit-hooks`) on push/PR to `main`, each calling the matching `make` target (`make lint`, `make format`, `make test`, `make docs`, `make hooks`) so the Makefile stays the single source of truth for what CI runs.
- `.github/workflows/initialize-repository.yml` is the one-time setup workflow. It only runs if `template_package/` still exists (its first step is an idempotency guard), validates `package_name`/`cli_name` inputs against PEP 8 / PEP 508 conventions, then renames the package dir, rewrites `Makefile`/`pyproject.toml`/imports/docs via `sed`, runs `make validate`, and commits + pushes directly to `main`.

## Known gaps (see if relevant to your task)

- No `LICENSE` file (added manually via GitHub's web UI on a per-project basis, not part of this template).
- `pyproject.toml` `authors` (`Your Name` / `your.email@example.com`) is a placeholder the init workflow does **not** replace — it must be fixed manually after initializing a real project.
